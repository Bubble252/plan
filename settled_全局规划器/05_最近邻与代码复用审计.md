# 最近邻与代码复用审计

记录日期：2026-10-24

文档性质：M0/M1 之间的新颖性与复用审计。本文只冻结“哪些工作已经覆盖了什么、哪些仓库可以碰、哪些不能碰”，不替代论文级系统综述，也不把摘要级证据写成全文结论。

## 1. 结论先行

### 1.1 Scoop-check 结论

**Level 3 — Medium Overlap（中等重叠）**。

没有发现一篇论文完整覆盖 Paper P 的核心句，但“在规划/控制中保留备用机动或恢复能力”已经不是空白：

- Backup CBF 系列已经把“备用控制策略可达”变成运行时安全约束；
- DR-bCBF 和输出反馈 bCBF 已经处理扰动、输入约束与状态估计误差；
- Fault-Tolerant NMPC + HOCBF 已经在水下推进器故障下做运行时安全控制；
- Resilient Motion Planning for Free-Flying Space Robots 和 A Model for Optimal Resilient Planning Subject to Fallible Actuators 已经在**规划阶段**显式考虑执行器故障。

因此，Paper P 不能只主张“我们考虑了恢复能力”。可暂时保留的 delta 是：

> 在三维海流、长细体欠驱动 REMUS 100 的全艇体扫掠、有限执行器能力和故障诊断延迟下，把恢复可行性作为**全局动力学路径搜索的沿途约束**，并输出可审计的有限有效期证书，而不是只在执行期做 CBF 过滤或在离散 MDP 中做故障规划。

如果后续实现只是“预计算可达集 + RRT*”且没有 AUV 特定的动力学/海流/诊断延迟机制，重叠度会升到 **Level 2 — High Overlap**，该主张将只剩应用迁移价值。这个升级条件必须写进 M7 的 Go/No-Go 记录。

## 4. 关键证据摘要

### 4.1 规划阶段考虑故障的工作

- **N2 Resilient Space Robot**：把执行器故障建模为 Markov 链，用预计算 backward reachable sets（BRS）判断每个航点在剩余推进器集合下是否仍可继续任务，再用 RRT* 串接航点。它明确以“故障后任务成功概率”为目标，并做了物理平台故障注入。这直接覆盖了“规划时就保留故障后退路”的一般思想。
- **N3 Fallible Actuators**：把“执行器会随使用而失效”写进 MDP 状态和价值函数，允许规划器为关键执行器留余量。其优势是计算上的 lattice/state re-use，但实验是网格世界，不是连续三维动力学、海流或长细体碰撞。
- **N1 Fault-Tolerant NMPC + HOCBF**：把推进器健康写进 NMPC 和 HOCBF，实时做推力重分配；在 BlueROV2 Heavy 上验证渐进推进器故障。它覆盖的是**故障后的运行时控制**，而不是规划时对整个路径的恢复可行性负责。

### 4.2 Backup CBF 与安全滤波

- **N12 Backup CBF**：控制不变集由固定 backup policy 的前向积分隐式构造；在线只需做 CBF-QP。它证明了 backup CBF 在温和假设下相对度为 1，并与 HJ/SOS 方法比较。关键限制是：它默认状态、动力学和故障模型足够准确，且是在线滤波问题。
- **N7 DR-bCBF**：对未建模但有界的扰动，用 nominal flow 与 disturbed flow 的误差球构造鲁棒不变集。它适合处理海流/模型误差，但没有显式建模“推进器突然降效”和“诊断延迟”。
- **N4 Timed Reach–Avoid backup CBF**：把 timed reach–avoid/STL 规格编码进 backup CBF-QP，并用 contractive implicit sets 解决有限时间收敛问题。它证明“高层任务 + 连续控制”的统一并不新；新的空间只能落在**全局路径搜索**和 **AUV 特有的能力退化**上。
- **N5 Multiple Constraints backup CBF**：处理时变、时不变和输入约束，强调安全滤波 QP 的可行性。它与 Paper P 的输入约束/备用控制部分高度相邻，但仍是运行期滤波器。
- **辅助文献 Output Feedback bCBF**：在只有状态估计且有输入界时，用估计流周围的误差包络保证真实状态安全。若 Paper P 的证书要考虑状态估计和诊断延迟，这篇是必须对照的公式来源。
- **辅助文献 Backup-Based Safety Filters Review**：指出 backup 类安全滤波的常见保守性来自“用备用机动的可行性代表当前策略的持续安全”。Paper P 不能把“有备用机动”直接等同于“名义路径安全”，必须报告保守性和无解率。

### 4.3 AUV 安全规划与海流规划

- **N8 AUV HOCBF**：离线生成满足执行器约束的 minimum-snap 多项式参考，在线用时间/状态相关 HOCBF-QP 修正 backstepping 控制器。它已经证明“AUV + 安全轨迹生成 + CBF”成立，因此 Paper P 不能把这一组合本身当作贡献。
- **N6 Safe MPC + robust CBF**：针对 AUV 的模型失配、离散化截断误差和外部扰动，使用 MHE 近似鲁棒 CBF。它覆盖“AUV 在不确定模型下安全规划”的一部分，但没有故障恢复或诊断延迟。
- **N9 DRL + 海流**：欠驱动 AUV 在未知海流中用 DDQN 和复合奖励做路径规划。它是学习型海流基线，不是安全证书方法。
- **N11 PSO + DDPG + ALOS**：完整系统包括改进 PSO 全局路线、DDPG 局部避障和三维 ALOS 制导；论文结论明确说多动态障碍场景仍不如带曲率约束的 DWA。适合复刻系统基线、验证海流跟踪，但不能作为恢复能力证据。
- **N10 Dual-Layer AUV**：摘要明确说“全局可行路线仍可能在执行中失败”，因此用 risk-aware Informed-RRT 生成参考走廊、risk-constrained DDQN 做局部动作，并设置阈值触发重规划。它覆盖了“全局规划 + 局部风险重规划”的组合，但摘要没有执行器故障、恢复证书、海流能量或诊断延迟；由于无全文，仍不能据此判断其失败模式和安全保证。

### 5.3 判定与 delta

**总体判定：Level 3 — Medium Overlap。**

一句话 delta：

> Unlike Resilient Motion Planning for Free-Flying Space Robots under Actuator Failures, which maximizes post-failure mission probability with precomputed reachable sets and RRT* in a weightless environment, the proposed work evaluates recovery feasibility along candidate trajectories of a slender underactuated AUV under three-dimensional ocean current and finite actuator authority, producing a planning-time certificate that explicitly accounts for diagnosis delay and whole-body clearance.

中文版本：

> 与依赖预计算可达集和 RRT* 的航天器 resilient planning 不同，本文针对长细体欠驱动 AUV，在三维海流、全艇体扫掠和有限执行能力下，把恢复可行性作为全局路径搜索的沿途约束，并显式处理故障诊断延迟，输出可审计的有限有效期证书。

### 5.4 已被覆盖与仍可主张

已经被覆盖或高度相邻的内容：

- 用 backup controller 或 backreachable set 判断“当前状态是否还能退回安全区”；
- 在输入约束、扰动、状态估计误差下构造鲁棒 backup CBF；
- 在水下推进器故障下做 NMPC + HOCBF 的运行时重分配；
- 在规划阶段考虑执行器故障，并优化故障后的任务成功概率；
- AUV 的安全轨迹生成、海流感知路径规划和 DRL/PSO/ALOS 系统集成。

仍可能成立的差异：

- 把恢复检查放进**全局动力学路径搜索**，而不是只在当前状态做一次 CBF-QP；
- 用**全艇体扫掠和长细体欠驱动动力学**改变路径选择，而不是把 AUV 当点质量；
- 把**执行能力退化 + 诊断延迟**作为规划输入，输出带假设、有效时间和失败原因的证书；
- 在相同信息、相同计算预算下，与“动力学规划 + 输入约束 CBF”和“BRS/RRT* resilient planning”做可重复对照。

不能再作为独立贡献的主张：

- “首次在安全控制中考虑备用机动”；
- “首次在规划中考虑执行器故障”；
- “AUV + CBF 安全轨迹生成”；
- “只要轨迹无碰撞就安全”。

## 6. 对实验设计的直接影响

### 6.1 强基线必须增加两类

现有 H1 主表已有 A*、改进 PSO、动力学 RRT*、海流感知轨迹优化、动力学规划 + CBF。根据本轮审计，至少还要加入：

1. **Resilient planning 近邻基线**：用预计算可达集/backreachable set 加 RRT* 的简化版本，模拟 N2 的规划时故障思路；这是检验“恢复约束是否只是航天器方法的换壳”的关键。
2. **Runtime fault-tolerant 近邻基线**：NMPC/HOCBF 或输入约束 CBF 的运行时故障处理版本，检验“规划时保留退路”相对于“故障后滤波”的独立价值。

如果这两类基线在相同信息和计算预算下达到同等安全效果，Paper P 必须收缩为 AUV 工程贡献或并入后续安全层论文。

### 6.2 必须预注册的因子和指标

- 诊断延迟：0、0.5、1、2 s；不能只做无延迟。
- 故障族：单推进器失效、推力下降、舵效下降、组合退化。
- 剩余执行能力：足以返航、只能维持定深、只能短时机动。
- 指标：故障后任务成功率、time-to-safe、证书覆盖率、证书有效期、无解率、保守性开销、规划时间。
- 近邻对照：N2 式概率成功率和 Paper P 的确定性证书不能混为一个指标；必须并列报告。

### 6.3 论文表述边界

- 不宣称连续时间、任意故障和任意海流下的保证；第一版只宣称在离散检查点和给定故障集合内的有限证书。
- 不把“备用机动存在”写成“名义路径持续安全”；应同时报告名义路径的 clearance、约束违反和证书失效点。
- 不把 DRL/PSO/ALOS 复刻结果当作恢复性证据；它们只用于系统基线和仿真接口验证。

### 7.1 `UUV-Motion-Planner` 的可复用边界

这个仓库是候选里最接近 AUV 全局规划的：它有 `dubins.cpp`、`path_planning.cpp`、`traj_opt.cpp`，核心源码约 2,600 行，地图和 AUV 参数也较完整。但它的风险同样明确：

- `src/CMakeLists.txt` 指向 `/opt/ros/melodic/share/catkin/cmake/toplevel.cmake`，是 ROS 1 工程，不是 ROS 2；
- 依赖 PCL 1.7、Eigen3 和 OpenBLAS，编译环境接近 Ubuntu 18.04；
- 没有单元测试、没有 CI、没有 `test` 目标；
- `package.xml` 的 `<license>` 仍是 `TODO`，与根目录 MIT 不一致，直接 vendor 会产生合规歧义；
- 其 Dubins 扩展假设水平/垂直曲率半径固定，不能直接替代 REMUS 100 的舵效、速度和全艇体约束。

允许做的事情：把 Dubins 路径生成、路径简化、LBFGS 轨迹优化中的**小算法片段**移植为独立 Python 函数，保留 MIT 版权声明，并用我们自己的测试验证数值行为。禁止的事情：把整个 catkin 包作为依赖、把 ROS 1 消息层带进算法核心、或在没有测试的情况下直接复制状态机。

### 7.2 许可证风险

- 没有根目录许可证的仓库默认受版权保护；公开可见不等于授予复制、修改或再分发权利。
- MIT/Apache-2.0 仓库也必须保留许可证、版权和来源；如果未来 vendor 代码，在 `THIRD_PARTY_NOTICES.md` 记录仓库 URL、commit、文件路径和修改摘要。
- 不把论文 PDF、第三方仓库的 `requirements.txt` 或数据集提交到 Git。
- 本项目的算法核心继续使用 Python dataclass/Protocol；第三方 ROS 1/C++ 代码只能作为离线参考或独立适配器，不进入 `contracts.py`。
