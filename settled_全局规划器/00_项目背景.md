# 全局规划方向项目背景

记录日期：2026-10-22；决策更新：2026-10-23

文档性质：方向草案。用于统一研究问题、假设和实验边界，不替代文献综述，也不代表路线已经完全冻结。

## 1. 为什么做全局规划

现有材料中的全局规划最初被定义为“有全部特权信息、已知地图上的 A* 路线规划”。它工程成熟、容易先跑通，但如果只做到“栅格地图 + A*”，科学贡献不足，也无法解释后续感知、局部避障和控制误差如何影响任务。

结合 `research/10_分层架构与论文组合路线比较.md`，本方向把问题提升为：

> 不仅要求路径当前无碰撞，还要求沿着路径的每个关键状态，在给定海流、执行能力和诊断延迟下，仍存在一条可执行的备用机动。

这使全局规划从“上游寻路模块”变成一个有独立问题定义、基线、指标和止损条件的研究方向。

## 2. 研究对象与场景

### 2.1 暂定对象

第一版只采用 REMUS 100 作为主平台，AUV533 后置为跨平台扩展：

| 平台 | 用途 | 原因 |
|---|---|---|
| REMUS 100 | 首篇 Paper P 的主实验平台 | 已有 PVS 6-DOF 模型、参数完整、单次实验快，且有 MSS 独立实现可做数值对照 |
| AUV533 | 首篇闭合后的可选跨平台扩展 | 长细比约 14:1、单桨四舵、不能悬停；只有需要证明跨平台泛化时才进入实验 |

BlueROV2 暂不作为本方向主平台。它更适合后续全驱动安全层、近距巡检和语义导航。AUV533 也不进入首篇关键路径，避免把模型迁移、平台差异和算法问题混在一起。

### 2.2 暂定场景

- 三维有界水域，含静态球体、圆柱、长方体、门框和峡谷/走廊。
- 海流先采用三维均匀流，再加入随深度变化的剪切流和慢时变流。
- 起始状态、目标区域、初始速度和航向均可配置。
- 第一版障碍与环境状态为 oracle；第二版加入地图误差、定位漂移和感知中断。
- 故障不要求由本方向诊断，但规划器需要读取“可用执行能力集合”或“健康不确定集合”。

### 2.3 暂定任务

给定起点、目标区域、三维地图、海流场、艇体模型和执行能力范围，输出：

1. 一条从起点到目标区域的三维动力学可行轨迹；
2. 每个关键节点的碰撞裕度、海流代价和可恢复性余量；
3. 一组备用机动或备用轨迹，以及证书的有效条件；
4. 无可行解时的明确失败原因，例如转弯半径不足、海流超过能力、恢复空间不足或执行器饱和。

## 3. 系统位置与接口

```text
任务/语义目标
      ↓
信念世界模型（地图、定位、海流、健康、不确定性）
      ↓
全局规划器（本方向）
      ↓  轨迹 + 可恢复性证书 + 失败原因
局部规划 / 安全滤波 / 控制分配
      ↓
执行器
```

本方向负责“去哪里、沿什么轨迹走、沿途是否留有退路”，不负责高频避障、控制跟踪和故障诊断。与局部规划的分工是：

- 全局规划：低频、三维、全航段、显式考虑海流/能量/恢复能力。
- 局部规划：高频、有限视场、处理新出现障碍和跟踪偏差。
- 安全层：执行阶段认证与修正，优先保证当前和近期安全。

## 4. 研究问题

### 4.1 主问题

> 在三维海流、长细体动力学和执行能力退化条件下，如何规划一条名义可行且沿途保留可恢复退路的路径，并量化这种保守性带来的时间、能量和任务成功率变化？

### 4.2 子问题

1. 海流和速度相关舵效如何改变全局路径的可行域与最优路径？
2. 长艇体全包络扫掠与最小转弯半径如何影响狭窄场景中的可通行性？
3. 如何用有限备用机动库近似高维可恢复集合，并给出可审计的保守证书？
4. 恢复约束在什么海流、速度、障碍密度和诊断延迟范围内产生稳定收益？
5. 与“普通动力学规划 + 输入约束 CBF”相比，在规划阶段保留退路是否仍有独立价值？

## 5. 假设与证伪条件

| 假设 | 内容 | 证伪条件 |
|---|---|---|
| H1 | 海流感知和全艇体扫掠能减少强流/狭窄场景中的约束违反 | 与几何 A* + 事后安全滤波相比，成功率、clearance 或安全性无稳定改善 |
| H2 | 恢复余量能降低故障诊断延迟后的碰撞和任务损失 | 强基线已经达到同等结果，或恢复约束只增加路径长度而没有安全收益 |
| H3 | 欠驱动、有限转弯半径、全艇体包络与海流耦合使问题显著区别于质点/全驱动规划 | 在 REMUS 100 上，简化质点/全驱动模型与完整模型的最优路径和安全边界几乎一致 |
| H4 | 有限备用机动库可以给出有用且可计算的保守证书 | 证书过于保守导致大多数场景无解，或无法预测真实恢复失败 |

论文级主张成立前，至少要通过 H1 与 H2 的强基线对照；H3 是平台差异化证据，H4 是方法可实现性证据。

## 6. 候选贡献

当前只把这些写成“候选贡献”，不提前写成已成立结论。

1. 面向长细体欠驱动 AUV 的三维海流感知动力学规划公式。
2. 以胶囊体/多球体扫掠表示全艇体碰撞，而不是点机器人近似。
3. 基于有限备用机动库的状态依赖可恢复性约束和保守证书。
4. 时间、能量、clearance 与恢复余量的多目标 Pareto 分析。
5. 诊断延迟、海流强度和剩余执行能力的三维安全边界实验协议。

如果第 3 项无法与 backup CBF、gatekeeper 或 contingency planning 形成可验证差异，应主动撤回该创新主张，把工作收缩为第 1、2、4 项或并入后续安全执行论文。

## 7. 与相邻技术方向的关系

| 技术方向 | 本方向如何使用 | 本方向不承担什么 |
|---|---|---|
| 感知/建图 | 接收占据地图、ESDF、语义障碍和不确定性 | 不做声光融合、目标检测和完整 SLAM |
| 海流辨识 | 接收海流估计及误差界，规划时做鲁棒代价 | 不把海流估计器本身作为主贡献 |
| 动力学辨识 | 使用已验证的艇体模型、执行器模型和能力范围 | 不重新做完整参数辨识 |
| 局部规划/CBF | 把全局轨迹交给局部层，并预留局部修正空间 | 不用全局规划替代高频避障 |
| 容错控制 | 接收健康状态、可用执行器集合和诊断延迟界 | 不做故障诊断算法和底层重构控制 |
| VLA/VLN | 为语义目标提供几何可达性和可恢复性检查 | 不在本阶段训练 VLA 或做语义 grounding |
| 能量管理 | 把能量消耗作为代价和约束 | 不单独研究电池/推进系统建模 |

这条分工保证全局规划可以独立形成论文，同时也为后续论文提供统一接口。

## 8. 实验等级

| 等级 | 环境 | 目的 | 是否进入论文主结果 |
|---|---|---|---|
| E0 | 纯算法单元测试 | 验证图搜索、碰撞、插值、代价和证书逻辑 | 否 |
| E1 | PVS REMUS 100 | 算法闭环、基线、候选方法和主实验 | 是 |
| E2 | MSS/Octave REMUS 100 与 Python 独立实现 | 数值一致性、模型可信性检查 | 是（模型验证） |
| E3 | OceanSim/HoloOcean | 高保真感知/环境压力测试 | 条件性，后置 |
| E4 | MSS/Octave AUV533 与 Python 独立实现 | 首篇闭合后的跨平台扩展 | 否，首篇不依赖 |

原则：先用 E0/E1 找到算法错误，再用 E2 验证 PVS 模型没有静默错误，之后才允许做论文级结论。不能因为 OceanSim 或 HoloOcean 更“真实”，就跳过模型验证和强基线；也不能把 AUV533 迁移当作首篇论文的前置条件。

## 9. 基线、指标与统计

### 9.1 基线

1. 三维栅格 A*：几何最短路径，无动力学。
2. 三维 RRT*：几何采样规划，无动力学。
3. 动力学 RRT* 或运动基元搜索：考虑转弯和速度约束。
4. 海流感知轨迹优化：考虑海流但无显式恢复证书。
5. 普通动力学规划 + 输入约束 CBF/事后安全滤波：强工程基线。
6. 当前方法：在规划阶段加入恢复约束和备用机动证书。

若第 5 项在相同信息和计算预算下达到同等安全效果，则停止把“可恢复性”作为独立论文贡献。

### 9.2 指标

| 类别 | 指标 |
|---|---|
| 任务 | 成功率、到达时间、路径长度、能耗 |
| 安全 | 碰撞率、最小全艇体 clearance、约束违反次数、无可恢复证书比例 |
| 恢复 | 故障后存活率、time-to-safe、备用机动可用率、证书有效率 |
| 计算 | 规划时间、节点扩展数、内存占用、超时率 |
| 保守性 | 相对最短路径的长度增加、能耗增加、Pareto hypervolume |

所有指标必须同时报告均值、分布和失败样本，不能只报成功案例。

### 9.3 统计协议

- 调试阶段可用 10–20 个固定种子，但不能作为论文证据。
- 论文主实验每个配置至少 100 个预先定义的独立 episode；零碰撞主张需要按单侧 95% 上界解释，n=100 时上界约 2.95%，不是“零风险”。
- 故障时刻、诊断延迟、海流方向和障碍布局必须预注册，不能看完结果后挑场景。
- 规划器与 plant 尽量不共用同一理想模型；REMUS 100 至少做 PVS/MSS 数值对照。

## 10. 首个最小闭环

首个闭环只回答“规划器是否按契约工作”，不回答论文创新是否成立：

1. 在固定三维场景中生成起点、目标和均匀海流。
2. A*、RRT* 和动力学基线分别生成轨迹。
3. 用统一下采样和碰撞检查评估轨迹。
4. 对每个关键节点计算一个简化恢复余量。
5. 输出统一 JSON/CSV 结果和图。
6. 人工检查无解原因和明显错误路径。

首个闭环的验收是接口、指标和可复现性，而不是方法性能。

## 11. 风险与停止条件

| 风险 | 早期信号 | 应对 |
|---|---|---|
| 新颖性不足 | 强基线已覆盖恢复约束 | 收缩为水下长细体/海流/全包络工程贡献，或并入 Paper S |
| 恢复证书过保守 | 大多数场景无解 | 缩小故障集合、缩短证书有效期、改用有限机动库 |
| REMUS 100 模型/跟踪不可信 | PVS 与 MSS 的对照轨迹显著不一致，或跟踪误差吞掉规划差异 | 先修模型与跟踪接口，不把问题归因于全局规划算法 |
| 场景过大 | 规划时间和内存不可控 | 降低地图分辨率、分级规划、限制主实验场景 |
| AUV533 扩展风险 | 后置迁移时结论与 REMUS 100 不一致 | 作为外部有效性讨论，不反向阻塞首篇 Paper P |
| 工程量失控 | 同时接感知、局部规划和 VLA | 回到 oracle 地图与单一主平台 |

阶段 No-Go 条件：若 M3/M4 仍无法稳定复现 A*、RRT*、REMUS 动力学闭环与统一指标，暂停新方法开发，只保留基准和工程报告。该门按证据是否闭合判断，不按日期判断。
