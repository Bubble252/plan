# 全局规划方向技术栈

记录日期：2026-10-22；仿真节点更新：2026-10-23

文档性质：技术方案草案。原则是先把算法、模型和评价解耦，再决定是否引入更重的仿真器和优化器。

## 1. 技术选择原则

- 规划核心不依赖 ROS、Isaac Sim 或特定仿真器，保证单元测试可独立运行。
- 第一版只使用 CPU 可运行的轻量栈，避免 GPU 仿真成为算法迭代瓶颈。
- 所有实验由 YAML 配置和固定种子驱动，结果可重放。
- 先实现强基线，再实现候选方法；不允许先写“新算法”再补对照。
- 大资产不入普通 Git；代码、参数、场景配置和小型回归数据入库。

## 4. 核心数据契约

所有规划器和实验共用同一组对象，避免每个算法各自定义状态和结果。

| 对象 | 最小字段 | 说明 |
|---|---|---|
| `VehicleSpec` | 长度、直径、质量、状态维度、速度/加速度/舵角/推力限制 | 平台无关的约束描述 |
| `State` | 位置、姿态、线速度、角速度 | 三维 NED 或统一世界坐标 |
| `ObstacleMap` | 边界、障碍原语或栅格、分辨率、ESDF 可选 | 第一版支持解析障碍与栅格 |
| `CurrentField` | 采样函数、时间、空间范围、误差界 | 先均匀流，再扩展 |
| `CapabilitySet` | 健康执行器、剩余效能、诊断延迟界 | 用于恢复检查 |
| `PlanRequest` | 起点、目标、地图、海流、平台、风险/恢复参数 | 一次规划输入 |
| `Trajectory` | 时间戳、状态、控制、参考速度、clearance | 至少支持线性插值和零阶保持 |
| `RecoveryCertificate` | 备用机动、有效状态域、有效时间、保守假设 | 没有证书时显式标记 |
| `EvalResult` | 成功、碰撞、约束违反、长度、时间、能量、规划时间、失败原因 | 统一 JSON/CSV |

坐标系、角度单位、深度正方向和海流方向必须在 `contracts.py` 与文档中一次写清，不能在不同模块中混用。

## 5. 规划算法路线

| 阶段 | 算法 | 作用 | 是否主方法 |
|---|---|---|---|
| 基线 1 | 三维栅格 A* | 几何最短路径、地图与指标验证 | 否 |
| 基线 2 | 三维 RRT* | 采样规划与复杂空间对照 | 否 |
| 基线 3 | 动力学 RRT*/运动基元 | 转弯、速度、海流约束 | 强基线 |
| 强基线 4 | 海流感知轨迹优化 | 对照“只优化名义轨迹” | 强基线 |
| 强基线 5 | 动力学规划 + 输入约束 CBF | 检验是否有独立恢复价值 | 最强对照 |
| 候选 | 恢复约束动力学规划 | 在搜索中保留备用机动和证书 | 待验证 |

恢复检查先采用有限机动库，不直接求解 12 维 Hamilton–Jacobi 可达集。候选机动可包括：

- 最大制动/减速；
- 最大上浮或下潜；
- 最小半径转向；
- 沿当前流场退出；
- 进入最近安全走廊或终端安全集。

证书必须写清适用条件和有效期，不能把“事后能找到一条轨迹”包装成在线保证。

## 6. 仿真与被控对象

### 6.1 REMUS 100

REMUS 100 是首篇 Paper P 的主平台。优先复用 `python/PythonVehicleSimulator-master/src/python_vehicle_simulator/vehicles/remus100.py`，但必须通过适配层调用，避免规划器依赖其内部状态。

用途：

- 建立轨迹跟踪与规划闭环；
- 检查深度/航向、速度限制、海流和统一指标；
- 作为 Paper P 的主实验结果；
- 用 MSS `SIMremus100` 做独立数值对照，检查 PVS 模型和接口是否有静默错误。

2026-10-25 已增加 `dynamics/remus100.py` 有状态适配器。它只接受已分配并限幅的 `Remus100ActuatorCommand`，返回同步的 `SimulationSnapshot`；`ActuatorCommand` 本身只是平台无关的时间协议。适配器默认从仓库内 PVS 源码加载，可用 `PVS_SOURCE_DIR` 覆盖路径。PVS REMUS 100 内置海流仍是水平均匀流，垂向分量和剪切流会被显式拒绝，三维海流需要后续模型扩展。

### 6.2 AUV533（后置可选）

只有当 REMUS 100 的基线、恢复证书和强基线对照已经闭合，才启动 AUV533 跨平台扩展。届时用 MSS/Octave 作为独立数值参照，Python 侧只实现规划需要的降阶模型和执行器约束。必须对照：

- 直航；
- 阶跃舵；
- zigzag；
- 均匀海流；
- 深度剪切/三维海流。

在模型对照通过前，不把 AUV533 的规划结果写成论文结论；AUV533 也不阻塞首篇 Paper P。

### 6.3 高保真仿真

OceanSim/HoloOcean 仅作为 E3 压力测试。接入顺序是：

1. 先保证规划器输出标准轨迹；
2. 再写仿真器适配器；
3. 最后替换地图/感知输入。

不能让仿真器 API 进入规划核心。

2026-10-23 已在 8 × 4090 服务器安装 HoloOcean 2.3.0 和 `Ocean` 世界包，并通过 `PierHarbor-Hovering` 的 headless `reset()`/`step()` smoke test。安装路径、校验值和限制见 `doc/HoloOcean安装记录.md`。这次安装不等于 REMUS 100 高保真模型已验证，也不改变“首篇先用 PVS/MSS 闭合算法与模型”的顺序。

`gpufree-container` 也补装了同一版本，Python 包、环境、世界包哈希和 ZIP 完整性均通过；但该容器当前只有 root 且没有 GPU，UE 拒绝以 root 启动，所以只能标记为“安装完成、运行未验证”。这不影响以 PVS/MSS 为主线的 M0/M1 工作。

同一台服务器也已安装 Isaac Sim 5.0.0.0 和 OceanSim 1.0（上游 `main` 提交 `7ab3a3a`）。隔离环境为 `/data/yhx/underwater-robotics/envs/conda_envs/oceansim`，源码与官方资产都位于 `/data`，缓存已重定向到数据盘。无 `DISPLAY` 的 headless smoke test 在物理 GPU 0 上完成：水下相机返回 `640×480` 非黑帧，浊水前后平均绝对差为 `13.12`；气压计读数与静水压力公式相差小于 `0.001 Pa`；成像声呐返回 `396×90` 扫描图。完整路径、资产清单和复现命令见 `doc/OceanSim_8x4090安装记录.md`。

这条链路当前只证明环境可用，不证明 REMUS 100 的动力学、控制器或规划闭环已经迁移到 OceanSim。Paper P 的主实验仍是 PVS 动力学仿真 + MSS 数值对照；OceanSim 只在需要高保真光学/声呐输入时作为 E3 条件性平台接入。

## 7. 场景与配置格式

建议每个场景使用一个 YAML：

```yaml
name: canyon_uniform_current
world:
  bounds: [[-50, 50], [-50, 50], [0, 80]]
obstacles:
  - type: sphere
    center: [10, 0, 30]
    radius: 4
current:
  type: uniform
  velocity: [0.3, 0.1, 0.0]
vehicle: auv533
start:
  position: [-40, 0, 20]
  yaw_deg: 0
  speed: 3.0
goal:
  position: [40, 0, 40]
  radius: 3
```

场景、车辆、海流和实验参数分开存放，禁止在脚本中硬编码。每个实验配置必须包含 `seed`、`scenario_set`、`planner`、`baseline`、`episodes` 和输出目录。

## 8. 测试策略

| 测试层 | 内容 | 目标 |
|---|---|---|
| 单元测试 | 坐标变换、插值、碰撞、代价、证书逻辑 | 每个函数可独立验证 |
| 契约测试 | 所有规划器输出同一 `Trajectory`/`EvalResult` | 防止接口漂移 |
| 回归测试 | 固定场景、固定种子、固定参数 | 结果可重复 |
| 数值测试 | REMUS 100 PVS 与 MSS 状态对照；AUV533 仅在扩展阶段加入 | 防止模型静默错误 |
| 端到端测试 | 一个场景全流程运行 | 检查配置、日志和输出 |

## 9. 结果与可复现性

- 每次运行写入 `outputs/<run_id>/config.yaml`、`git_commit.txt`、`metrics.csv`、`summary.json`。
- 图中必须带场景名、种子、规划器、平台和关键参数。
- 失败运行也保留，并记录失败原因；不能只保存成功轨迹。
- 结果按配置和种子索引，禁止手工覆盖同名目录。
- 论文表格由脚本从 `summary.json` 生成，避免手工复制数字。

## 10. Git 与大文件

当前仓库没有首次提交，且根目录存在压缩包、解压资产和仿真快照。禁止直接 `git add .`，否则可能把数百 MB 的 RAR/MAT/PDF 和 `.venv` 一起入库。

建议：

- 只暂存本方向文档、源代码、配置和小型测试数据。
- `outputs/`、`*.csv` 大结果、`*.mat`、`*.rar`、场景二进制包加入 `.gitignore` 或外部数据目录。
- 必须版本化的大文件使用 Git LFS 或记录下载来源与校验和。
- 提交前用 `git status --short` 和 `git diff --cached --stat` 检查暂存范围。
